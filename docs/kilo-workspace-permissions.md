# Права Kilo в папке без Git

Kilo проверяет файловые инструменты относительно `Instance.worktree`, а не
обязательно относительно открытой папки. Без `.git` worktree — корень диска
(`/` на Unix). Поэтому `specs/**` не совпадает с
`Ramium/1c-vibe/specs/TASK-.../03_solution_spec.md`, хотя порядок deny/allow верен.

Установщик Kilo вычисляет worktree (ближайший `.git`, включая файл linked worktree,
и `git rev-parse --git-common-dir`; без Git — корень файловой системы), затем
привязывает ключи `permission.read` и `permission.edit` к точному пути Target.
Пример для `C:\Ramium\1c-vibe` без Git: `Ramium/1c-vibe/specs/**`.
Общий `*` сохраняется. Старые `**/specs/**` и подобные алиасы превращаются в
тот же точный префикс, а не в разрешение для всех проектов на диске.

В Kilo-шаблоне developer также добавлен отсутствовавший fallback `edit: "*": deny`:
разрешены только перечисленные каталоги, включая после слияния с глобальными defaults.
Модель, MCP, bash/skill/task и тело агента не меняются.
`glob`/`grep` принимают шаблон/поисковый запрос, поэтому их правила не переписываются
как файловые пути. Адаптеры Claude/OpenWork эта правка не меняет.
Символы `*` и `?` в вычисленном префиксе блокируют установку: иначе имя каталога
стало бы расширяющим права шаблоном.

## Установка и обновление

Используйте обычный `install.ps1 -Tool kilo -Target <проект> -Mode update`.
Не требуется `git init`, глобальный edit allow, удаление deny или общий Force.
Манифест содержит хеш именно установленной версии. Повторный update при неизменном
расположении идемпотентен. Создание/удаление Git-репозитория, смена worktree или
перемещение проекта требуют повторной установки: префиксы привязаны к месту установки.
Не копируйте установленные агенты в другую папку как канонические шаблоны.

Корпоративная установка должна обновить свой upstream pin до коммита с исправлением,
затем выполнить штатный normalize/install/patch. Обновление отдельного публичного
клона само по себе не меняет корпоративный pin. Если установщик сообщает
`skip (user-modified)` для агента, проверьте отличия и корпоративную нормализацию;
не стирайте изменения принудительно. Частные полные agent overrides требуют
отдельной проверки: их файловые правила должны быть привязаны к тому же Target.

## Проверки

`python core/scripts/test_permission_paths.py` запускает настоящий установщик
в папке без Git (с пробелами/Unicode), в Git-корне, вложенной папке и linked worktree.
Проверяются все метаданные и тела семи агентов, запись трёх SDD-артефактов аналитиком,
запись исходников разработчиком, ограничения reviewer, запрет соседних проектов,
а также повторный update. Тест входит в smoke-фазу validate; нужны PowerShell и
`requirements-dev.txt`. Это проверка конфигурации и Git/worktree-контракта, а не
вызов живой сессии Kilo 7.8.15: подтверждение записи самим аналитиком на Windows
остаётся приёмочной проверкой после корпоративной установки.
