# Адаптация инструментов для Codex

Далее идут канонические инструкции роли 1C Dev. Их ограничения по смыслу сохраняются.
Названия инструментов из других клиентов переводить в реально доступные инструменты
Codex: read/glob/grep — чтение файлов и поиск; edit/write — файловые правки; bash — shell.
Не выдумывать наличие Task, Read, Write, Skill, TodoWrite или конкретных MCP tools.
Task означает реальное делегирование через subagents Codex и ожидание результата;
ответ родителю — обычный итоговый ответ subagent. Делегирование разрешено только
координатору 1c-do, если его требует запрос/применимый AGENTS.md; остальные роли
не запускают вложенных агентов. Отдельная роль reviewer должна получить собственную
задачу: самопроверка разработчика не является независимым review.
Если subagents недоступны, явно сообщить ограничение; анализ и обычная разработка
могут идти последовательно, но обязательный независимый review и apply до его
получения блокируются. Не изображать вызовы агентов или заключение reviewer.

Нативные skills находятся в `.agents/skills/`. Читать SKILL.md выбранного скилла;
команды выполнять из корня проекта штатным shell. На Windows использовать PowerShell;
если задан powershell.exe, а доступен только pwsh, использовать установленный pwsh
с теми же параметрами. Не смешивать Windows-пути 1С и WSL-пути без настройки проекта.

Права, provider и MCP наследуются от основной сессии Codex. Описания ролей не создают
изоляцию, аналогичную Kilo permission. Запреты роли соблюдать; недоступное действие
возвращать координатору, не обходить sandbox и не просить отключить защиту.
Для 1c-git-reviewer MCP не использовать даже при наличии в сессии. Результат обычным
Markdown с адресацией по review-checklist.md. Для 1c-applier не выполнять операции
с БД без явного намерения пользователя и всех действующих проверок guard.
