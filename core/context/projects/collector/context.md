# Контекст проекта: `collector`

Проект-специфичный контекст для конфигурации, лежащей в `projects/collector/src/**`.
Общий (схемный) контекст — в `INSTRUCTIONS.md`. Этот файл читают агенты по полю
«Проект» из Task-брифа (определяет `1c-do`, см. шаг 1.5 алгоритма `1c-do`).

## Платформа и конфигурация

- Платформа: **1С:Предприятие 8.3.27**, управляемые формы
- Язык: **BSL**
- Конфигурация (Name из метаданных): **`Коллекционер`**
- Vendor: не указан — **полностью самописная конфигурация**
- Version: `3.1.7.02`
- База: создана на базе **БСП** (подсистема `СтандартныеПодсистемы`).
  Версия БСП хранится в данных (регистр `ВерсииПодсистем`), в XML-исходниках недоступна —
  определяется в рабочей ИБ.

## Источники

- `collector` — основная конфигурация (Коллекционер)

## Бизнес-домен

Коллекционирование + торговля коллекционными предметами + файловый менеджер (БСП):

- **Предметы коллекционирования:**
  - монеты (`КлассификаторМонет`, `РазновидностиМонет`, `СерииМонет`, `Номиналы`,
    `МонетныеДворы`, `МатериалыМонет`);
  - банкноты (`КлассификаторБанкнот`);
  - Lego (`КлассификаторМинифигурокLego`, `НаборыLego`, `СостоянияНаборовLego`).
- **Учёт коллекций:** `ПредметыКоллекции`, `Коллекции`, `Изображения`, `ОценкиСостояния`.
- **Торговля коллекционными предметами:** `ПоступлениеТоваровУслуг`, `РеализацияТоваровУслуг`,
  `УстановкаЦенНоменклатуры`, `ОбъявлениеОПродаже`, `СписаниеТоваров`,
  `ОприходованиеТоваров`, `ВводОстатков`.
- **Специфичные документы:** `РазборНаборовLego`, `ИзменениеСоставаКоллекции`,
  `ИскомыеПредметыКоллекционирования`.
- **Файловый модуль (БСП):** `Файлы`, `ПапкиФайлов`, `ТомаХраненияФайлов`, `СведенияОФайлах`,
  синхронизация с почтой/интернет-сервисами.
- **Регистры:**
  - накопление — `ОстаткиКоллекции`, `ОстаткиНоменклатуры`, `ПокупкиИПродажи`;
  - информация — `СоставыКоллекций`, `СоставыНаборовLego`,
    `КонсолидированныеДанныеРазновидностейМонет`, `ЦеныНоменклатуры`, `ДополнительныеСведения`.

## Часто используемые модули

Конфигурация самописная на базе БСП. Перечисление справочное — аналитик `1c-analyst` имеет
полный доступ к `projects/collector/src/CommonModules/**` и читает модули точечно по
необходимости. Большинство модулей — БСП-типовые (`АдресныйКлассификатор*`,
`АдминистрированиеКластера*`, `АнализЖурналаРегистрации*` и др.).

## Summaries

Summaries проекта `collector` лежат в `.kilo/context/projects/collector/summaries/`
(per-project, кэш — `.kilo/context/projects/collector/summaries/.cache.json`).
Каталог пока не существует — регенерация через `scripts/build_summaries.py`
(режим `--scan --objects` для добавления объектов в индекс и построения summaries).
Проект выводится из пути объекта автоматически.

## База данных

- Реестр баз проекта: `.v8-project.json` в корне репозитория — единственный источник истины
  (читают db-* скиллы).
- База разработки: `collector-dev` — файловая, `C:\Ramium\Bases\Collector`, пользователь `Admin`.
- Разрешение: по `id`/`aliases` (`collector`) либо по `configSrc` (`projects/collector/src`).
- Применение правок в живую ИБ — агент `1c-applier` (только по явному запросу пользователя
  «внеси/примени правки в базу» через `1c-do`).
- Для регистрации новой базы — `/db-list add` (правит `.v8-project.json`).
