# Requirements — функциональные требования

Каталог для персистентных требований, формулируемых аналитиком `1c-analyst`
для разработчика `1c-developer`.

## Назначение

Передача функциональных требований между агентами без ручной ретрансляции
через чат. Аналитик сохраняет требования в файл, разработчик читает их
перед реализацией и при необходимости дописывает уточняющие вопросы
в тот же файл.

## Формат имени файла

`<тип>.<имя>__<краткое>.md` — транслит, дата опциональна.

Примеры:
- `Document.lvl_Smeta__dobavit_rekvizit.md`
- `Catalog.lvl_Raboty__proverka_zapolneniya.md`

## Структура файла

```markdown
# Требования: <объект> — <краткое описание>

## Объект
Тип и имя объекта 1С.

## Контекст задачи
Бизнес-смысл и предпосылки.

## Требования
Нумерованный список функциональных требований.

## Вопросы/уточнения (заполняет разработчик)
Вопросы разработчика к аналитику при конфликте с кодом.

## Ответы аналитика (заполняет аналитик)
Ответы на вопросы из предыдущей секции.
```

## Жизненный цикл

1. Аналитик создаёт файл при формулировании требований для разработчика.
2. Разработчик перед реализацией проверяет наличие файла по объекту.
3. При конфликте требований с кодом разработчик дописывает блок
   «Вопросы/уточнения» и сообщает пользователю о необходимости возврата
   к аналитику.
4. Пользователь через `1c-do` перенаправляет вопрос аналитику —
   аналитик заполняет «Ответы аналитика».
