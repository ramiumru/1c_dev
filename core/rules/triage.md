# Triage-уровни

Классификация правок перед маршрутизацией. Определяет глубину процесса и gate'ы.

## Уровни

### docs-fix
Только проза (README, комментарии-описания, документация), без BSL/metadata.
- **Gate:** проверка путей/ссылок.
- **Без BSL-валидаторов.**
- Без SDD spec, review, scope_hash.

### quick-fix
Одна логическая правка в одном BSL-модуле, ≤ `QUICKFIX_MAX_LINES` изменённых строк (поле в `.dev.env`,
по умолчанию 40), ИЛИ одно изолированное добавление метаданных (без проводки).
- **Без promotion-триггеров** (см. ниже).
- **Gate:** двухстрочный план → правка → `bsl-check.py` → `*-validate` (для XML) → доставка.
- Без SDD spec, review, scope_hash, applier_guard.

### sdd
Всё остальное или material doubt.
- Полный SDD-поток: analyst → gate → developer → (review для high-risk) → (post-SDD summaries).
- Обязателен для promotion-триггеров.

## Promotion-триггеры (переопределяют quick-fix → SDD)
Если правка затрагивает хотя бы один пункт ниже — это SDD, не quick-fix:
- Транзакции/проведение документов
- Движения регистров
- RLS/права доступа
- Регламентные/фоновые задания
- Публичные экспортные процедуры (контракт)
- Изменение метаданных (структура: новые реквизиты, ТЧ, типы)
- Интеграционные контракты (HTTP/Web-сервисы, обмены)
- Массовое изменение данных
- Финансовые расчёты

## Quick-fix gate'ы (облегчённые, без SDD)
1. `python scripts/bsl-check.py <файл.bsl>` — структурная проверка (кодировка, парные
   конструкции, orphaned-код). ERROR — исправить перед возвратом.
2. `*-validate` скилл — для XML-метаданных (если правка metadata).
3. **НЕ нужен:** SDD spec, review, scope_hash, applier_guard.

## Поведение при обнаружении promotion-триггера в quick-fix
Если при quick-fix обнаружен promotion-триггер — СТОП, вернуть `1c-do` с пометкой
«требует SDD: найден promotion-триггер <описание>». `1c-do` повторно классифицирует как SDD.
