# BSL-стандарты (level-стандарт)

Правила именования, комментариев, запросов, БСП, проверок заполнения, форм, расширений.
Параметры проекта (префикс, компания, версия платформы) — в `.dev.env` (корень проекта,
поле `PREFIX`/`COMPANY`/`PLATFORM_VERSION`). При первой правке — прочитать `.dev.env`.

## Соблюдать

- **Именование:** префикс из `.dev.env` (поле `PREFIX`) для новых реквизитов/ТЧ в типовых
  объектах и новых объектов (см. также `{{CONTEXT_DIR}}/projects/<проект>/context.md`);
  подчинённые элементы нового объекта — без префикса.
- **Комментарии изменений:** `// ++ #НомерЗадачиGitLab` … `// -- #НомерЗадачиGitLab`. Без фамилий,
  дат, emoji.
- **Собственные модули:** закомментированный код запрещён.
- **Типовые модули:** типовой код не удалять — оформлять комментированием.
- **Документирование процедур/функций:** экспортные — обязательный doc-комментарий
  (Описание/Параметры/Возвращаемое значение); при правке существующих — актуализировать.
  Неэкспортные нетривиальные — рекомендуется. (level §8.7.)
- **Запросы:** оформление как в конструкторе; комментарии вне текста запроса.
- **БСП-функции:** использовать вместо самописных (перечень — стандарт, п.12).
- **Проверки заполнения:** `ОбработкаПроверкиЗаполнения` модуля объекта /
  `ОбработкаПроверкиЗаполненияНаСервере` формы.
- **История данных:** не включать «Обновлять историю данных сразу после записи».
- **Замеры производительности:** для новых объектов (открытие формы, запись, проведение); замер
  пользовательского процесса — начинать и завершать на клиенте.
- **Формы:** типовые формы — только программно; рекомендуемо
  `<префикс>ДобавитьЭлементыФормы()` в конце `ПриСозданииНаСервере` (префикс — из `.dev.env`).
- **Расширения:** не предлагать как основной способ обычной бизнес-доработки.
- **Осознанное нарушение стандарта:** только с комментарием «Почему нарушаем стандарт?».

Full-read (полные секции §9, §10) — только для нетривиального кода; Summary-чек-лист (стр. 9-37)
— при сомнении.
