# Сверка стандартов после правки (для 1c-developer)

## Self-verification перед выдачей результата (generic)

Короткая самопроверка **перед возвратом любого BSL-кода/запроса** пользователю или в
`06_change_report.md` — и в обычном implementation, и в `artifact-only` (read-only артефакт
без правки source). Применять к тому, что реально есть в результате (не всё сразу):

- **Сигнатуры** вызываемых существующих процедур/функций подтверждены реальным источником
  (прочитанный исходник, code-index/поиск, info-скилл, project MCP) — не по памяти.
- **Обязательные параметры**: у каждого вызова заполнены обязательные параметры (и не
  потеряны необязательные, влияющие на поведение).
- **`Экспорт` и доступность**: вызываемый метод другого модуля — экспортный и достижим из
  текущего контекста вызова.
- **Клиент/сервер**: вызов допустим в текущем контексте (клиентский/серверный/внешнее
  соединение), если контекст влияет на вызов.
- **Конструкции языка запросов**: использованные конструкции языка запросов 1С
  синтаксически корректны и стоят в допустимом месте запроса.
- **Не уверен в API/конструкции** — свериться с доступным справочным источником
  (`platform_help`, `v8std`, info-скилл, существующий код-аналог), а не додумывать
  сигнатуру; останется неуверенность — пометить в «Допущения / Что проверить».

Это одна короткая самопроверка, а не review-процесс: не разворачивать в отдельный
reviewer-flow (в artifact-режиме — без повторного полного анализа).

## Иерархия стандартов
При написании и ревью BSL применять в порядке убывания приоритета:
1. **Стандарт level** — `{{CONTEXT_DIR}}/standards/standards.example.md` (первичный, выше стандартов 1С).
2. **Стандарты 1С** — MCP `v8std` (вторичный, сверка фрагментов/тем).
3. **Чек-лист ручной верификации** — `AGENTS.md` (fallback в офлайне).

Конфликт level ↔ 1С → приоритет level (явно отметить со ссылкой на пункт level).
Конфликт level ↔ `AGENTS.md` → приоритет level.

## Шаг 10 алгоритма: проверка после правки
После правки XML-метаданных — запустить `*-validate` (`meta-validate`/
`form-validate`/`mxl-validate`/`skd-validate`/`role-validate`/`subsystem-validate`/
`xdto-validate`/`interface-validate`/`cf-validate`/`cfe-validate`) по пути объекта.

После правки BSL-модулей — запустить `python scripts/bsl-check.py <файл.bsl>`
(структурная проверка: BOM, CRLF, баланс `Если/КонецЕсли`, `Процедура/КонецПроцедуры`,
`Функция/КонецФункции`, `Цикл/КонецЦикла`, `#Область/#КонецОбласти`, маркеры
`// ++/-- #TASK`, orphaned-код вне процедур). ERROR уровня — исправить перед возвратом;
WARN (lone LF, дисбаланс маркеров) — исправить при возможности.

## Сверка BSL (3 уровня, level обязателен всегда)
- **level-стандарт** — по маппингу (точечно для тривиальных, полные §9/§10 для нетривиальных):
  именование, комментарии, отсутствие закомментированного кода, запросы, БСП-функции,
  проверки заполнения, история данных, замеры, документирование процедур/функций (§8.7).
- **`AGENTS.md`** — чек-лист ручной верификации (синтаксис 8.3.27, кириллица, области,
  запросы вместо циклов, транзакции/блокировки, бизнес-логика вне форм, SDD-артефакты).
  Применять **всегда**.
- **`v8std` (MCP)** — **только** если правка содержит хотя бы одну конструкцию-триггер.
  Иначе — пропустить (fallback `AGENTS.md` достаточен). Недоступен при срабатывании → лог
  `WARN v8std-offline-fallback`, fallback на `AGENTS.md`. При сомнении в тривиальности — вызывать `v8std`.

## Конструкции-триггеры v8std (расширенный список)
- Модальные вызовы: `ОткрытьФормуМодально`, `Предупреждение`, `Вопрос`, `ОткрытьЗначение`,
  `ВыбратьЗначение`.
- `ВЫБРАТЬ РАЗРЕШЕННЫЕ` / `РАЗРЕШЕННЫЕ` в текстах запросов (RLS-влияние).
- Транзакции: `НачатьТранзакцию`, `ЗафиксироватьТранзакцию`, `ОтменитьТранзакцию`,
  `НачатьТранзакциюНаСервере` (8.3.27).
- Вызовы БСП-функций из списка level §12.
- Обмены: планы обмена, регистры обмена, обработки обмена.
- Регламентные задания (`РегламентноеЗадание.*`, методы `Запланировать`, `Выполнить`).
- XDTO-обмен (пакеты XDTO, точки входа, сериализация).
- Подписки на события (`ПодпискаНаСобытие.*`) при правке обработчиков.
- Создание/правка экспортных процедур/функций (сверка doc-комментария).

Тривиальные правки (опечатка, комментарий, rename реквизита, простое присвоение,
косметика формы) — **v8std пропускается**, `AGENTS.md` достаточно.
