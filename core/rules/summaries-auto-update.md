# Авто-обновление summaries (для 1c-do)

Шаги 4.5 (post-developer не-SDD) и 6.5 (post-SDD) — автообновление summaries через `1c-tools`.

## Шаг 4.5: после не-SDD правки
После возврата `1c-developer` вне SDD-режима — если в ответе разработчика есть структурированный
список изменённых объектов (канонические заголовки `Документ.X`/`Справочник.X`/`ОбщийМодуль.X`/
и т.д.), выполнить гибридный роутинг обновления summaries идентично шагу 6.5:
- `grep` по `{{CONTEXT_DIR}}/projects/<проект>/objects-index.md` — все заголовки найдены →
  делегировать `1c-tools` в режиме `--objects` (Task, retry-once);
- хотя бы один отсутствует (новый объект) → делегировать `1c-tools` в режиме `--scan --objects`
  (Task, retry-once); лог `WARN auto-scan-triggered`.

Если ответ разработчика не содержит структурированных заголовков (тривиальная правка без явного
списка объектов) — пропустить автообновление, сообщить «summaries не обновлялся (тривиальная правка);
для обновления — `обнови summaries`».

## Шаг 6.5: после SDD-правки
После возврата `1c-developer` — через `read` прочитать `specs/<TASK-ID>/06_change_report.md`.
- Сначала проверить «Статус реализации». Если `не выполнено (блокировано)` или «Отклонения от
  спецификации» содержат блокирующий конфликт — **НЕ обновлять summaries**, записать лог
  `WARN sdd-implementation-blocked`, вернуть пользователю.
- Если статус `выполнено` / `выполнено частично` — из секции «Изменённые файлы» извлечь
  **только канонические заголовки объектов 1С** — токены с префиксами `Документ.`, `Справочник.`,
  `ОбщийМодуль.`, `РегистрСведений.`, `РегистрНакопления.`, `РегистрБухгалтерии.`, `РегистрРасчёта.`,
  `Отчёт.`, `Обработка.`, `Константа.`, `ПодпискаНаСобытие.`, `ПланСчетов.`, `ПланВидовХарактеристик.`,
  `ПланОбмена.`, `БизнесПроцесс.`, `Задача.`, `Роль.`, `ЖурналДокументов.`, `Подсистема.`.
  **Исключить** составные `МодульОбъекта`, `МодульМенеджера`, `МодульФормы` (сам `ОбщийМодуль.X`
  включать можно). **`Форма.<Тип>.<Имя>` — извлечь родительский объект** `<Тип>.<Имя>`.
  Дедуплицировать.
- **Гибридный роутинг:**
  - через `grep` по `{{CONTEXT_DIR}}/projects/<проект>/objects-index.md` проверить наличие каждого заголовка
    как строки `^# <Заголовок>$` (точное совпадение);
  - **если ВСЕ заголовки найдены в индексе** → делегировать `1c-tools` в режиме `--objects`
    (Task, retry-once): `python scripts/build_summaries.py --project <проект> --objects "<список>"`;
  - **если ХОТЯ БЫ ОДИН заголовок отсутствует** (новый объект) → делегировать `1c-tools` в режиме
    `--scan --objects` (Task, retry-once): передать канонические заголовки дословно;
    лог `WARN auto-scan-triggered`;
  - stdout добавить в ответ блоком «summaries обновлены: <список>» (или «обнаружены новые объекты,
    запущен --scan: <список>»). Report неполон/объекты неоднозначны → пропустить, сообщить
    «запустите обновление summaries вручную».
