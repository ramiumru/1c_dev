# Project sources: MCP + local (единая политика)

> Единый источник истины для приоритета источников проектного контекста и семантики типов MCP.
> Агенты (`1c-analyst`, `1c-developer`, `1c-reviewer`) подгружают это правило через `read`
> по триггеру «работа с проектом, у которого настроены MCP sources» (см. on-demand таблицы агентов).
> `1c-do` и `1c-applier` руководствуются поведенческими правилами ниже (без глубокого поиска).

## Sources проекта

Источники проекта описываются в машиночитаемом блоке (fenced `yaml`) в
`{{CONTEXT_DIR}}/projects/<проект>/context.md` (см. `examples/project-context.example.md` —
универсальный шаблон). Поддерживаемые типы источников:

| Источник | Назначение |
|---|---|
| `local` | Локальный Git checkout / workspace: `projects/<источник>/src/**`. Source of truth для edit. |
| `metadata` (mcp) | Поиск объектов метаданных, навигация по функциональной области, связанные объекты, первичный поиск места реализации. |
| `code` (mcp) | Поиск BSL-кода, методов/процедур, аналогичных реализаций, движений документов, запросов, call sites, паттернов (основа + расширение). |
| `platform_help` (mcp) | Вопросы о платформе 1С, встроенном языке, объектах/методах платформы, синтаксисе и API. |
| `standards` (mcp) | Источник стандартов разработки 1С (альтернатива/дополнение `v8std`). |

Поля `enabled`, `server`, `project_id`, `repositories` — только через placeholder или переменную окружения
Реальные корпоративные URL/UUID/credentials — **только** в локальном `context.md` (gitignored `projects/`,
overlay, `.dev.env`), **никогда** в публичном репозитории.

## Source priority policy

### Discovery / поиск реализации

Если соответствующий project MCP настроен (`enabled: true`) и доступен:

1. **MCP** (`metadata`/`code`) — поиск объектов/кода, навигация, первичное место реализации;
2. **локальные исходники** — уточнение найденного контекста (структура через info-скилл, точечный `read` BSL);
3. **локальный full-text/file scan** (`glob`/`grep` по `projects/<источник>/src/**`, per-project индексы
   `{{CONTEXT_DIR}}/projects/<проект>/objects-index.md`, `summaries/**`) — fallback;
4. только затем **общие знания модели**.

Если MCP отсутствует (`enabled: false`) или недоступен (runtime-ошибка/таймаут):

1. **локальные исходники** (`projects/<источник>/src/**`);
2. **локальные индексы/summaries**;
3. **общие знания модели**.

**MCP failure НЕ блокирует работу**, если локальные исходники доступны: лог `WARN mcp-unavailable-fallback`,
переход на локальные источники. Не блокировать задачу без необходимости.

### Перед изменением файла

MCP/индекс **не является** окончательным источником содержимого редактируемого файла. Перед `edit`
разработчик **обязан** прочитать актуальный локальный файл из workspace через `read` (source of truth).
MCP/индекс дают навигацию и ссылки, но не снимают необходимости читать файл перед правкой.

## MCP-only / read-only проект

Если для проекта настроен MCP, но локального Git checkout отсутствует (`local.enabled: false` или
`projects/<источник>/src/**` не существует`):

 разрешён **анализ** и **подготовка SDD/spec** (`01_context.md`, `03_solution_spec.md`, `05_test_scenarios.md`,
 `review.md`), но **запрещено фактическую модификацию исходников** — нет writable workspace.

В этом режиме (`read-only` / `mcp-only`):
- `1c-analyst` работает через MCP + общие знания (без локальных исходников);
- `1c-developer` — только анализ/реализация-план в `06_change_report.md` БЕЗ правки файлов; **обязан** явно сообщить: «проект в MCP-only/read-only режиме — фактическая правка исходников невозможна без writable workspace»;
- `1c-reviewer` — может проверять specification/design/context и доступный через MCP существующий
  код, давать findings/recommendations. **НО** не выдавать `approved` фактической реализации, которой
  нет в writable workspace / которую невозможно независимо сверить. Post-implementation `approved`
  требует независимо доступной фактической реализации. Apply без local workspace невозможен;
- `1c-applier` — MCP **не добавляется** (см. раздел «Агенты»); apply в MCP-only проекте невозможен (нет исходников для `db-load-xml`).

## Семантика типов MCP

### metadata/context MCP
- поиск объектов метаданных;
- навигация по функциональной области;
- определение связанных объектов;
- первичный поиск места реализации.

### code-index MCP
- поиск BSL-кода;
- использование методов/процедур;
- поиск аналогичных реализаций (особенно для движений документов — см. «Ключевые принципы 1С-разработки» в `1c-developer.md`);
- поиск движений документов / запросов;
- анализ call sites;
- поиск паттернов в основном репозит и расширении.

### platform-help MCP
Вопросы о: платформе 1С; встроенном языке; объектах и методах платформы; синтаксис и API.

### standards MCP
Источник стандартов разработки 1С (дополнение к `v8std` / `standards.example.md`).
**При расхождении** стандарта и существующего проектного паттерна агент **должен показать расхождения**, а не молга считать одно другим.

## Поведение по агентам

- **`1c-do`** — определяет project profile + available sources (из `sources`-блока `context.md`) + read-only флаг, передаёт в Task-брифе. Глубокий поиск кода самостоятельно не ведёт.
- **`1c-analyst`** — основной consumer: `metadata` MCP → `code` MCP → local fallback → `platform_help`/`v8std` при необходимости.
- **`1c-developer`** — `code` MCP для аналогичных реализаций (обязательно для движений документов, если MCP доступен); `standards`/`platform_help` MCP; **локальные исходники — обязательный источник перед `edit`**.
- **`1c-reviewer`** — read-only доступ к тем же lookup/reference sources (`metadata`, `code`, `standards`, `platform_help`). Независимая проверка, не полагаться только на ссылки developer.
- **`1c-tools`** — **не превращать** в generic MCP proxy; остаётся исполнителем `build_summaries.py` (local-only).
- **`1c-applier`** — MCP **не добавляется**. Детерминированный исполнитель guard/apply (local sources only).

## Permissions

Публичный frontmatter адаптеров сохраняет безопасный default: `mcp: "*": deny` (у `1c-analyst`/`1c-applier`/
`1c-tools`) и `mcp: { "*": deny, "v8std_*": allow }` (у `1c-developer`/`1c-reviewer`). Разрешения на
конкретные project MCP-серверы — **локальная конфигурация** (корневой конфигурационный файл инструмента
`kilo.json`/`openworks.json` или overlay), аналогично секретам в `.v8-project.json` / `.dev.env`.
В публичный репозиторий имена корпоративных MCP-серверов **не попадают**.

## Сводка режимов (graceful degradation)

| Режим | MCP | Local | Поведение |
|---|---|---|---|
| A | да | да | MCP discovery → local verification/edit (основной режим) |
| B | да | нет | analysis/spec работают; developer **не** выполняет edit (read-only/MCP-only) |
| C | нет | да | текущая схема продолжает работать (fallback на local; режим публичного репо) |
| D | настроен, недоступен | да/нет | `WARN mcp-unavailable-fallback` → local (как C/в); задача не блокируется |
