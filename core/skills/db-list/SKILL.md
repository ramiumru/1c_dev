# /db-list — Управление реестром баз данных

Управляет файлом `.v8-project.json` — реестром информационных баз проекта. Файл хранит параметры подключения, алиасы, привязку к веткам Git.

## Usage

```
/db-list                    — показать список баз
/db-list add                — добавить базу (интерактивно)
/db-list remove <id>        — удалить базу из реестра
/db-list show <id|alias>    — подробности по базе
```

## Формат `.v8-project.json`

Файл размещается в корне проекта (рядом с `.git/`). **НЕ коммитить** — в нём пути/учётки ИБ.

**Секреты (логин/пароль) НИКОГДА не хранятся в файле.** Указываются только имена
переменных окружения (`username_env` / `password_env`); агент/скилл читает значения
из окружения во время выполнения. Легаси-поля `user`/`password` ( plaintext )
**небезопасны**: при их обнаружении агент предупреждает и рекомендует миграцию на
`username_env`/`password_env`, а `1c-applier` отказывается продолжать.

```json
{
  "environment": "local",
  "v8path": "C:\\Program Files\\1cv8\\8.3.27.0000\\bin",
  "databases": [
    {
      "id": "local-demo",
      "name": "Локальная демо-база (тестовая)",
      "type": "file",
      "path": ".\\example-base",
      "username_env": "V8_USERNAME",
      "password_env": "V8_PASSWORD",
      "aliases": ["demo", "демо"],
      "branches": ["dev", "develop", "feature/*"],
      "configSrc": "projects/example/src"
    },
    {
      "id": "test-sandbox",
      "name": "Тестовый песочница (сервер, тестовый контур)",
      "type": "server",
      "server": "test-sandbox.example.test",
      "ref": "Example_Test",
      "username_env": "V8_TEST_USERNAME",
      "password_env": "V8_TEST_PASSWORD",
      "aliases": ["test", "тест"]
    }
  ],
  "default": "local-demo"
}
```

### Поля корневого объекта

| Поле | Тип | Обязательное | Описание |
|------|-----|:------------:|----------|
| `environment` | `"local"` / `"test"` / `"staging"` / `"production"` | да | Среда проекта. Отсутствие/пустое/неизвестное/`production` блокирует изменяющие операции (`1c-applier`, `applier_guard.py`). Не определяется по умолчанию и не угадывается по имени каталога/сервера/базы |
| `v8path` | string | нет | Каталог bin платформы 1С. Если не задан — автоопределение |
| `databases` | array | да | Массив баз данных |
| `default` | string | нет | id базы по умолчанию |

### Поля объекта базы данных

| Поле | Тип | Обязательное | Описание |
|------|-----|:------------:|----------|
| `id` | string | да | Уникальный идентификатор (латиница, без пробелов) |
| `name` | string | да | Человекочитаемое имя |
| `type` | `"file"` / `"server"` | да | Тип подключения |
| `path` | string | для file | Путь к каталогу файловой базы |
| `server` | string | для server | Адрес сервера 1С |
| `ref` | string | для server | Имя базы на сервере |
| `username_env` | string | нет | Имя переменной окружения с именем пользователя 1С (безопасно, не коммитится) |
| `password_env` | string | нет | Имя переменной окружения с паролем 1С (безопасно, не коммитится) |
| `aliases` | string[] | нет | Альтернативные имена для быстрого доступа |
| `branches` | string[] | нет | Git-ветки или glob-паттерны (`release/*`, `feature/*`), привязанные к этой базе |
| `configSrc` | string | нет | Каталог XML-выгрузки конфигурации |

> ⚠️ Легаси-поля `user` / `password` (plaintext в файле) **запрещены**. Используйте
> `username_env` / `password_env`. Переменные окружения не логируются, не
> включаются в отчёты/SDD-артефакты и не выводятся в ошибках полностью.

## Алгоритм разрешения базы данных

Этот алгоритм используется ВСЕМИ навыками (`db-*`, `epf-build`, `epf-dump`, `erf-build`, `erf-dump`) для определения целевой базы.

1. Если пользователь указал **параметры подключения** (путь, сервер) — используй напрямую
2. Если пользователь указал **базу по имени** — ищи совпадение в таком порядке:
   1. По `id` (точное совпадение)
   2. По `aliases` (совпадение в массиве с учётом морфологии: «тестовую» = «тестовая» = «тестовой»)
   3. По `name` (нечёткое совпадение с учётом морфологии и регистра)
3. Если пользователь **не указал** базу — сопоставь текущую ветку Git с `databases[].branches`:
   - Точное совпадение: ветка `dev` → `"branches": ["dev"]`
   - Glob-паттерн: ветка `release/2.1` → `"branches": ["release/*"]`
4. Если ветка не совпала — используй `default`
5. Если не найдено или неоднозначно — спроси пользователя
6. Если файл `.v8-project.json` не найден — спроси параметры подключения и предложи создать файл

После выполнения: если использованная база не зарегистрирована — предложи добавить через `/db-list add`.

> ⚠️ Среда: изменяющие операции (load/update/create/web-publish/web-unpublish)
> требует явного допустимого `environment` (`local`/`test`/`staging`; `production`
> и отсутствие/неизвестное значение блокируются). Это проверяет `1c-applier` и
> `applier_guard.py` (см. 1c-applier). Для просмотра списка (`/db-list`) среда не требуется.

### Разрешение учётных данных (из окружения)

Логин/пароль читаются **только из переменных окружения** по именам в
`username_env` / `password_env` базы (legacy-поля `user`/`password` в файле
небезопасны — при их наличии предупредить и рекомендовать миграцию, изменяющие
операции не выполнять):

```powershell
$user = [Environment]::GetEnvironmentVariable($db.username_env)
$pass = [Environment]::GetEnvironmentVariable($db.password_env)
```

Никогда не выводите и не логируйте значение пароля. В шаблоны команд других
скиллов передавайте через переменные, а в отображаемой строке редьте (`***`).

### Автоопределение платформы

Если `v8path` не задан в конфиге:

```powershell
$v8 = Get-ChildItem "C:\Program Files\1cv8\*\bin\1cv8.exe" | Sort-Object -Descending | Select-Object -First 1
```

## Операции

### Показать список баз

Прочитай `.v8-project.json`, выведи таблицу:

```
ID      Имя           Тип      Путь/Сервер              По умолч.
dev     Разработка    file     C:\Bases\MyApp_Dev       ✓
test    Тестовая      server   srv01/MyApp_Test
```

### Добавить базу

Спроси у пользователя через AskUserQuestion:
- id, name, type (file/server)
- path (для file) или server + ref (для server)
- `username_env` / `password_env` — имена переменных окружения для логина/пароля
  (НЕ сами логин/пароль; plaintext-поля `user`/`password` не использовать)
- aliases, branches (необязательно)

Добавь в массив `databases`. Если это первая база — установи как `default`.
Корневое `environment` обязательно; при отсутствии спроси у пользователя.

### Удалить базу

Удали из массива `databases` по id. Если удаляемая была `default` — спросить новый default.

### Подробности по базе

Выведи все поля конкретной базы.

## Формирование строки подключения

Для использования в шаблонах команд других навыков:

**Файловая база:**
```
/F "<path>"
```

**Серверная база:**
```
/S "<server>/<ref>"
```

**Аутентификация** (добавляется если задано `username_env` и переменная окружения непуста):
```
/N"<$user>" /P"<$pass>"
```
где `$user`/`$pass` получены из переменных окружения `username_env`/`password_env`.

> **Важно**: между `/N` и именем пробела нет. Между `/P` и паролем пробела нет. Если
> пароль пуст — опусти `/P` целиком. **Никогда** не подставляйте значение пароля
> литералом в файл/лог/отчёт/SDD-артефакт и не передавайте видимым аргументом, если
> есть безопасная альтернатива (переменная окружения). Учтите, что платформа 1С CLI
> принимает пароль только аргументом `/P` — это экспозиция на уровне списка процессов
> ОС; предпочтительна Windows-аутентификация или file-based credentials там, где
> платформа это поддерживает.
